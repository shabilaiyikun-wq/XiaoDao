# 液态连接原型 · 评估与结论

参考实现：FluidKit `src/liquid/geometry.ts` + `src/liquid/tension.ts`（MIT，见
`desktop/LICENSES/fluidkit-MIT.txt`）。

结论先说：**几何与滞回都实现并验证通过了，但原型保持关闭，没有接进正式外观。**
原因是它与两条已经写进代码的视觉要求直接冲突，冲突不是风格分歧，是可以用数字和
引用指出来的。下面把冲突、数字、以及「怎么打开」都写清楚。

---

## 1. 选了哪一对，为什么

**岛体右端圆弧 ↔ 消息小球**（`_host` 的右端 ↔ `_ball`）。

选择原因，按重要性排序：

1. **几何是精确的，不是近似的。** 岛体圆角半径是 `r = Math.Min(30, h / 2)`
   （`IslandWindow.Apply`）。idle 是 52×30、第二层是 112×38，两档的 `h` 都 ≤ 60，
   于是 `r` 恰好等于 `h / 2` —— 这时候岛体右端**整段就是一个正半圆**，
   圆心 `(w - r, h / 2)`。小球挂在同一水平中线上。所以这一对严格是两个圆，
   正是参考算法适用的形状，不需要任何"看起来差不多"的近似。
   （展开态 `h = 206` 时 `r = 30 < h/2`，右侧变成直边，参考的圆—圆算法就不适用了。
   这一点本身也是下面的冲突之一。）
2. **所有量都是编译期常量**：`IdleW/IdleH/PlayW/PlayH`（`Ui.cs`）、
   `NotifyGap = 10`、`NotifyBall = 34`（`IslandWindow.cs`）。探针量的和正式代码用的是
   同一组数，没有运行时测量可以互相扯皮。
3. **它是工程里唯一"一个圆刻意与一块体之间留了一条显式缝隙"的地方。**
   `NotifyGap` 在代码里被直接称作"那道缝隙"（`ApplyBallAnim` 注释）。
   缝隙就是连接颈要去填的东西 —— 别的地方根本没有需要连接颈的几何。
4. 它**不涉及玻璃材质、不涉及桌宠动画**，符合"一次只动一处"的约束。

## 2. 实现了什么

| 文件 | 内容 |
| --- | --- |
| `desktop/LiquidGeometry.cs` | 圆—圆切线点 + 双贝塞尔连接颈 → `PathGeometry`；颈宽的绝对测量；缠绕方向归一化 |
| `desktop/LiquidTension.cs` | 滞回状态机（连接 1.02 / 断开 1.30）、颈宽曲线、**绝对最小颈宽门槛**、有效断开点 |
| `desktop/LiquidPair.cs` | 真实对象对的常数镜像（独立编译时需要） |
| `desktop/LiquidProbe.cs` | 隔离验证：数值矩阵、滞回差分实验、光栅 + DPI |
| `desktop/LiquidProbeMain.cs` | 独立探针的入口（只被 `build-liquid.cmd` 编译） |
| `desktop/build-liquid.cmd` | 只编几何 + 张力 + 探针 → `LiquidProbe.exe`，不碰主程序 |
| `desktop/LICENSES/fluidkit-MIT.txt` | MIT 正文 + 移植范围说明 |

对参考实现的**实质修改**（不是美化，是修 bug，逐条写在文件头）：

1. `acos` 参数夹紧。参考实现直接调 `Math.acos(...)`，浮点误差越界时在 C# 里得到
   `NaN`，而 `NaN` 坐标塞进 `Geometry` **不抛异常**，只是让这一帧图元静默消失。
2. 颈宽改成**实测绝对量**（DIP）。参考实现只有 0..1 的相对 `waist` 系数，
   球一小颈就细成一条丝，没法作为"最小宽度"的依据。
3. **状态只在几何真的产出之后才记账。** 参考实现先 `connected.add(key)` 再拼路径，
   而 `bridgePath` 在包含/退化/够不着时返回空串 —— 会出现"状态说连着、画面什么都没有"，
   反过来就是闪一下。
4. 配对键与遍历顺序无关（参考实现用 `${a.id}|${b.id}`，换个顺序状态就全丢）。

## 3. 验证结果

跑法（两条路都通）：

```
desktop\build-liquid.cmd /run           # 独立探针，不碰主程序
desktop\WinIsland.exe --liquid-probe --liquid-out DIR
```

最新一次：**6 个分组、全部断言通过，退出码 0。**
产物在 `work/liquid-probe/`（`work/` 在 .gitignore 里）：`liquid-probe.txt`、
`liquid-probe.json`、`liquid-matrix.png`、`liquid-connected.png`、`liquid-snapped.png`。

| 组 | 覆盖 | 结果 |
| --- | --- | --- |
| S1 | 参考实现自带测试的 4 个用例 + 缠绕方向 + 并集无洞 | 通过 |
| S2 | 真实对象对（idle / 第二层） | 通过，并测出冲突（见 §4） |
| S3 | 4 组半径 × 8 方向 × 3 档拉伸（96 例） | 全有限、无 NaN、颈宽单调 |
| S4 | 滞回、快速反向抖动 | 见下 |
| S5 | 相切 / 重叠 / 远离 / 包含 / 最小颈宽门槛 | 通过 |
| S6 | 96 / 120 / 144 / 192 四档 DPI 光栅 | 见下 |

### 滞回确实消掉了临界抖动

在断开距离上做「正反抖动 240 帧」的**差分实验**（同一份数据同时喂给带滞回的和
不带滞回的判据）：

```
跨断开线抖动 240 帧: 有滞回翻转 1 次，无滞回对照翻转 130 次
带内抖动     240 帧: 翻转 0 次
快速反向 (1.05 <-> 1.25) ×200: 翻转 0 次
单调退出 121 帧内状态翻转 1 次（应为 1）
```

「跨线抖动」允许断开一次（那是真实退出），但断完不许再翻回来；
无滞回对照在同一段数据上抖了 130 次。这条就是滞回存在的全部理由。

### 断开不留细丝 / 裂口 / 一帧闪烁

- **细丝**：`MinNeckWidth = 2.0 DIP` 是硬门槛，量出来窄于它就不画（宁可不连）。
  真实半径下参考自带的相对下限已经保证 6.8 ~ 21 DIP，门槛只在球小到 1~2 DIP 时才生效 ——
  `1.0/0.8` 那一对被判为"永不连接"，正是门槛在起作用。
- **裂口**：体和颈是**同一个 `PathGeometry`、同一条 nonzero 填充**，不是两块拼图，
  所以接缝处不存在"各画一半"的缝。探针在轴线上逐点 `FillContains` 断言连续。
- **一帧闪烁**：断开在这一帧**原子**发生（状态先清、几何这一帧就不产出），
  不淡出、不留残影。四档 DPI 下「断开帧两体之间像素数」实测全部为 **0**。

### DPI

解析颈宽 12.4862 DIP，四档 DPI 实测画出来的最细处：

| DPI | 期望 px | 实测 px | 断开帧带内像素 |
| --- | --- | --- | --- |
| 96 | 12.49 | 14 | 0 |
| 120 | 15.61 | 16 | 0 |
| 144 | 18.73 | 20 | 0 |
| 192 | 24.97 | 26 | 0 |

实测比解析值高 1~1.5 px 是两缘抗锯齿被计入（阈值 alpha > 40），随机型缩放；
关键是它**跟着 dpi/96 一起放大**，没有在任一档塌成一条细丝。

## 4. 为什么最终保持关闭（冲突）

### 冲突一：这一对静止时天生就压在临界距离上

推导很干净：两者同心高、小球落在缝隙外侧，所以

```
圆心距 d = r岛 + r球 + 缝隙
stretch  = d / (r岛 + r球) = 1 + NotifyGap / (r岛 + r球)
```

代入真实数字（`r球 = 17`、`NotifyGap = 10`）：

| 状态 | h | r岛 | stretch | 距断开线 (1.30) |
| --- | --- | --- | --- | --- |
| idle | 30 | **15**（= h/2） | **1.3125** | 超出 **+0.4 DIP** → 断 |
| 第二层 / compact | 38 | **19**（= h/2） | **1.2778** | 低于 **−0.8 DIP** → 连 |

临界岛端弧半径 `r* = NotifyGap / (1.30 − 1) − r球 = 16.3333 DIP`。
idle 的 15 在左、第二层的 19 在右 —— **整个 UI 横跨在阈值上**。

后果用探针实测确认过：

- **idle**：球从岛后滑出时会经过重叠区，于是真的连上；但滑到静止位**之前**
  （stretch 越过 1.30 那一刻）就断掉，断开时颈还有 6.8 DIP 宽。
  也就是说：一次弹出动画里会长出一根颈、然后掐断 —— 正是 "从岛后钻出来"
  这个动作被故意设计成**纯平移**要避免的东西。
- **第二层**：静止位 stretch 1.2778 < 1.30，所以滑出后那根颈**永远不断**，
  静止时以 8.2 DIP 宽永久横在岛体和小球之间，把 `NotifyGap` 那条缝隙填死。

**同一根颈在两层之间表现为相反的样子**：idle 是一闪而过的"长出来又掐断"，
第二层是"永久焊住"。这不是调参能解决的 —— 因为判据只有一个标量（岛端弧半径），
而 UI 恰好把它放在阈值两侧 1.33 DIP 的窄缝里。

### 冲突二：这条动画的"脖颈"已经被明确否过一次

`IslandWindow.cs` 里那段注释是原文：

> 球在 `_root` 里排在 `_host` 之前（见构造里那个 Insert），所以它还没滑出来的时候
> 整颗被岛体挡住，看上去就是从岛后面钻出来 —— 不需要裁剪、不需要遮罩、
> **也不需要任何形状变形**。上一版做"水滴分裂/脖颈"被否掉了，理由是突兀；
> 这一版只做一件事：平移。

所以"给这一对加连接颈"不是没人想过，是做过、被以"突兀"为由否掉，然后换成了纯平移。
原型把这件事做得更严谨（滞回、最小颈宽、无残留），但**没有改变"什么时候会长出颈"
这件事本身** —— 按上面的数字，它仍然是在一次 640ms 弹出动画的中后段长出来又掐断。
这是审美判断，不是缺陷修复，所以不该由原型单方面推翻。

### 冲突三：`_ballDock` 的裁剪边正好压在岛体右缘上

`BuildVisualTree` 里：

```csharp
_ballDock.Clip = new RectangleGeometry(
    new Rect(-NotifyGap, -4, NotifyBall + 200, NotifyBall + 8));
```

`_ballDock` 钉在 `岛体右边缘 + NotifyGap`，裁剪从 dock 局部 `-NotifyGap` 起 ——
两者相加正好是**岛体右边缘**。这条裁剪的存在理由写在注释里：岛体是半透明玻璃，
不裁的话球从底下滑过会被透视出来。

后果：任何想从岛体上长出来的连接颈，都会在岛体右缘**被这条裁剪硬切**。
而"颈与岛体融合"的观感要求颈能跨过那条边、并由岛体自身轮廓收边 ——
也就是必须改这条裁剪。改裁剪就是改消息球的渲染前提，属于任务里明确要求
"不要同时改"的那一类；而且改错会让球重新从玻璃里透出来。

### 冲突四：展开态几何不适用

展开态 `h = 206`，`r = min(30, h/2) = 30 < h/2`，岛体右侧是**直边**而不是圆弧。
参考算法是圆—圆；直边—圆是另一套切线构造（法向恒为 x 轴），不能靠"半径取大一点"
去近似。要覆盖展开态就得再写一个壁面变体 —— 而在展开态下缝隙是 10 DIP、
按任何度量都远超断开距离（stretch 量级 1.59），本来也不该有颈。
于是"只在 2/3 个状态里可能出现颈"本身又是一个新的不一致来源。

## 5. 保持关闭的具体含义

- 正式外观**一行没动**：没有往 `_root` / `_host` / `_ballDock` 里加任何元素，
  没有改 `_ball` 的任何属性，没有改裁剪，没有改动画曲线。
- `desktop/build.cmd` 只多了 4 个源文件到编译列表；它们不被任何绘制路径引用，
  唯一的调用点是 `Program.cs` 里 `--liquid-probe` 那条**在建窗口之前就 return** 的分支。
- 不传 `--liquid-probe` 时，程序行为与引入原型之前一致（进程仍是同一个单窗口 + 桌宠）。
- 桌宠动画、消息球逻辑、玻璃材质：**一处未改**。

### 如果以后要启用，需要先做决定的事

1. 让 idel 与第二层的「有颈／无颈」结论一致 —— 要么统一都有，要么统一都没有。
   最小的改法是**只调一个数**：把 `NotifyGap` 从 10 提到
   `(1.30 − 1) × (r岛 + r球) − ...` 之外，使两档都稳定在阈值同侧；
   但 10 这个缝隙是当前视觉的一部分，改它就是改外观。
2. 决定颈与岛体的融合方式：要么让颈层位于岛体之上并改用 `_shape` 做裁剪
   （需要重做 `_ballDock` 的裁剪语义），要么接受颈被岛体右缘平切。
3. 展开态要么补壁面变体，要么明确定义"展开时不画颈"并接受状态切换时的跳变。

在这三件事定下来之前，把它保持关闭是唯一不会破坏现状的选择。

## 6. 已知缺口

- `NotifyGap` / `NotifyBall` 在 `IslandWindow.cs` 里是 `private const`，运行时读不到，
  所以 `LiquidPair` 里存的是镜像值（`IdleW/IdleH/PlayW/PlayH` 会在
  `Program.cs` 里被 `Scenes.*` 覆盖，改 `Ui.cs` 会被探针抓到；这两个不会）。
  改这两个常数时必须同时改两处。
- 颈宽测量是数值式的（粗网格 + 局部细化），不是解析解；对本工程用到的
  1.5 ~ 34 DIP 半径，探针用加密采样交叉验证过，误差 < 0.02 DIP。
- S3 的单调性只在 stretch ∈ [0.95, 1.30] 上断言。再往里会逼近"一圆包含另一圆"的
  退化边界，那时参考算法给出的形状本身在塌缩，颈这个概念已不成立 —— 这是参考实现的
  特性，不是移植引入的。
