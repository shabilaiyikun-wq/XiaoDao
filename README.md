# xiaodao · 原生灵动岛（样式层 + 真实数据）

Windows 顶部灵动岛的原生实现，跑在真实桌面上：置顶、四角透明、岛外点击穿透、可拖动。
样式照《Windows 灵动岛 产品文档 v0.1》§5.1 / §8.1 / §8.2 做，尺寸和时长对着条款；
五个活动场景全部接**真实系统数据**，不是样张。

> 项目名 **xiaodao**　｜　位置 `E:\xiaodao`　｜　独立仓库，与 Dock（`E:\deskdock`）互不依赖。
> 可执行文件仍叫 `WinIsland.exe`，配置目录仍是 `%APPDATA%\WinIsland`——沿用旧名是为了不丢
> 你现有的待办、场景和位置记录。

- **基线**：按文档条款做，44 项验收。
- **无约束版**：放下尺寸区间与主题数量限制，只按视觉上限做一遍，13 项验收。
- **原生程序**：同样这套样式真的浮在桌面上，79 项像素验收 + 12 项交互验收。
- **真实功能**：媒体（SMTC）、音量（CoreAudio）、网络吞吐、麦克风/摄像头占用、倒计时。

## 先看这个

**要程序**：`desktop\build.cmd` 然后 `desktop\run.cmd`。一个 342 KB 的 exe 浮在桌面顶部，
不依赖浏览器、不依赖 .NET SDK、不依赖任何 NuGet 包（只用 .NET Framework 4.8 自带的
`csc.exe` + 系统自带的 WinRT 元数据）。没有音乐时它缩成一颗 52×30 的小球。

**要网页**：双击 `showcase.html` —— 不用构建、不联网、没有依赖。网页那套是纯视觉稿，
数据是假的；**要功能只能跑 exe**。

主视觉是一颗会变形的岛，浮在一张假窗口上；下面是控制条，可以现场切形态、活动、外观、取材。
其余展区依次是：三形态几何、六场景完整版面、四种外观、圆弧与连续圆角放大对比、
玻璃七层剖面、排版标尺与取色。

`style-demo.html` 是基线演示台（含弹簧参数滑块，用来找手感）；
`style-board.html` 是基线的静态对照板，用于评审。

| **右键** | 弹出菜单：场景 / 外观 / 取材 / 形态 / 截图 / 允许截图与录屏捕捉 / 拖出后从暂存移除 / 把剪贴板里的文件暂存 / 复位位置 / 退出 |
| **滚轮** | 切场景：媒体 → 计时器 → 剪贴板 → 待办 → 中转站 |

| **待办卡** | 点圈打勾、点文字改写；下面直接写新的，带时间就按时提醒 |
| **Alt+A** | 截图：拖出选区后还能微调，`Enter` / ✓ 完成，复制到剪贴板并落一张 PNG |

### 五个场景的真实数据源

| 场景 | 数据来自 | 接线方式 |
| --- | --- | --- |
| 媒体 | **SMTC**（系统音量键上方那个媒体浮层的同一套接口） | `Windows.Media.Control.GlobalSystemMediaTransportControlsSessionManager`，走系统自带 winmd |
| 音量 | **CoreAudio** 端点音量 | 手写 `IMMDeviceEnumerator` / `IAudioEndpointVolume` COM 互操作 |
| 传输 | **全网卡吞吐** | `NetworkInterface.GetIPv4Statistics()` 差值 |
| 会议 | **麦克风/摄像头占用** | `HKCU\…\CapabilityAccessManager\ConsentStore\{microphone,webcam}` 的 `LastUsedTimeStart/Stop` |
| 倒计时 | 本地 | 按 `Environment.TickCount` 真实经过时间扣减，睡过去再醒也不走偏 |

媒体这张卡是真读真写：曲名/艺人/专辑来自播放器，点 ⏯ 会让播放器真的暂停。
拿不到封面时退回渐变块；拿不到音频端点时显示 `--` 而不是假装 0%。

> 「传输」在产品文档里原指 AirDrop 式文件传输队列。Windows 没有系统级的传输队列可读
> （`IOperationsProgressDialog` 要挂在具体进程的 COM 对象上），这里改为**全网上下行速率**，
> 数据是真的，语义也站得住：岛显示的是「这台机器现在在传多少」。

### 环境自检

```bat
WinIsland.exe --selftest --log=selftest.log
```

日志里会有四条 `DATA`，把每条数据源的原始读数直接打出来（实机验证过）：

```
DATA media has=False app=媒体 status=Closed title='' artist='' pos=0/0 canNext=False canSeek=False
DATA audio avail=True vol=5% mute=False
DATA net rx=13.9KB/s tx=0KB/s
DATA meeting mic=False() cam=False()
```

`has=False` 是「此刻没有播放器在播」，不是接线坏了——开个播放器再跑一次就会看到曲名。

关键实现选择（详见 `style-spec.md` §10）：

- **窗口尺寸固定**为「展开尺寸 + 留白」，从不变。形变只改岛的绘制尺寸，没有一次 `SetWindowPos`。
- **穿透按超椭圆轮廓**判定，16ms 轮询 `GetCursorPos`，不是按窗口矩形——否则紧凑态会挡掉一大片桌面。
- **玻璃靠抓屏**：`Show()` 之前 `BitBlt` 一张全屏图，用 `ImageBrush.Viewbox` 按相对位置采样 + 模糊。
- **落影用描边**：三层同心 `Path` 共享同一份几何，不在每帧做模糊。
- **WinRT 不靠 SDK**：直接引用 `C:\Windows\System32\WinMetadata\*.winmd` + `System.Runtime.dll` 门面。
  但**不能**同时引 `System.Runtime.WindowsRuntime`——它的 `AsTask` 是针对合并版 `Windows.winmd` 编译的，
  和拆分版元数据对不上（`CS0012`/`CS1928`）。所以异步一律轮询 `IAsyncOperation.Status` + `GetResults()`。
- **卡片里的按钮不拖窗**：按下时先往上找 `Tag="act"`，命中就交给按钮，不进入拖拽。

## 三层（原生程序）

原生程序现在按**三层**工作，层与层之间由「有没有音乐在放」和「鼠标在不在岛上」自动切换：

| 层 | 触发条件 | 尺寸 | 圆角 | 屏幕上是什么 |
| --- | --- | --- | --- | --- |
| **1 · 空闲** | 没有媒体在播 | 52 × 30 | 15 | 一颗常转的小球，别的一概没有 |
| **2 · 播放中** | 有音乐、鼠标没进来 | 112 × 38 | 19 | 只有封面 + 五根律动条，**不显示任何文字** |
| **3 · 展开** | 鼠标移到岛上 | 416 × 156 等（按场景） | 30 | 完整卡片：曲名/艺人/控件，或其它四个场景 |

切换是自动的，不用点任何东西：

```
空闲 ──音乐出现──▶ 播放中 ──鼠标进来──▶ 展开
  ▲                    ▲                  │
  └──音乐结束──────────┴──鼠标离开────────┘
```

**为什么第一层要这么小。** 没音乐可播的时候，岛没有任何信息可供传达，那它就不该占地方。
52×30 是「能塞下一颗球」的最小尺寸，缩到这么小之后它基本不构成干扰。

**为什么第二层不放文字。** 播放中你通常不需要读曲名——扫一眼封面就知道在放什么。
把文字留到第三层，第二层就能一直保持 112×38，不会因为歌名长短忽宽忽窄。

渐变块兜底：拿不到封面时用当前「取材」的渐变代替，不会空一块。

基线（`style-demo.html`）：空闲 120×28 / 紧凑 220×36 / 展开 400×140，圆角 14 / 18 / 28。
网页版仍是手动切形态，三层自动机只在 exe 里有。

三版都用 `r = min(上限, height/2)`，只依赖高度，所以形变全程连续。
不能按状态二分——展开→收起时状态先切到紧凑，半径会从 30 跳回 78。

尺寸固定、岛心不动：窗口始终按「展开尺寸 + 留白」建，小尺寸时岛在窗口里水平居中，
所以从 52 长到 416 的过程中**岛心一动不动**，只有两边在伸展。

`--state idle|compact|expanded` 可以把某一层钉住（验收脚本靠这个拿可重复几何）；
不传就走自动机。

## 动效

弹簧 k=250 / c=24（ζ≈0.77），收起增益 ×1.75 / ×1.38，回弹约 2%。
基线实测展开 401–405ms、收起 275–286ms（符合 §8.2 的 350–450 / 250–300）；
无约束版 397–416ms；原生程序 398.5 / 280.8ms——三套同参，量出来就是同一条曲线。

无约束版另有逐元素错峰入场：容器标 `.stag`，直接子元素按 `nth-child` 依次上浮，
延迟 40ms + i×34ms，缓动 `cubic-bezier(0.34,1.42,0.64,1)`。

## 已知取舍

- 空闲态在原生程序里是一颗**旋转小球**（52×30）；网页版仍是呼吸点（网页那两版没跟着改）
- 毛玻璃必须带 `brightness(.7)` 压暗层，否则浅色壁纸下白字不够读
- 强调色要拆三个：`--acc` 装饰、`--acc-on` 实心压白字、`--acc-ink` 当文字色。
  少了第三个，霜白外观下浅紫压白底只有 2.01:1。
- `.island__view` / `.isl__view` 不常驻 `will-change`：常驻合成层会强制灰度抗锯齿，静止文字会发虚
- **律动条不是电平表**：`IMMDevice::Activate(IID_IAudioMeterInformation)` 在这台机器上直接抛
  `InvalidCastException`（换进程、换接口声明都一样试过）。所以第二层的五根条只表达「在播、在动」，
  **不表达「多大声」**——暂停即冻结，播放即起伏。音量场景同理，只显示真实音量值。
- **进度条已删除**（有实测依据）：真实播放器 B 站客户端在 SMTC 里报
  `IsPlaybackPositionEnabled=false`、`Position=0`、`Duration=0` —— 位置压根没有值，
  进度条会永远停在 0:00。自造会话里 `TryChangePlaybackPositionAsync` 虽然回 `True` 但位置也不动。
  所以删掉，媒体卡现在只有「封面 / 曲名 / 艺人 / 上一首·播放·下一首」。
  `Snap.MediaPct` 还留着，将来遇到真的支持 seek 的播放器可以直接接回去。
- **「传输」= 网络吞吐**，不是文件传输队列（原因见上）。
- **只认 SMTC**：不走 SMTC 的播放器（少数老程序）不会出现在岛里。
- 层切换只由「有没有媒体」驱动，还不认识音量/会议/传输这三类「事件」——
  比如插耳机、开麦时不会自动跳到对应场景，得右键手动选。
- **多个播放器同时挂着**时：优先选正在播的；全都没在播就选时间轴最近更新的那个。
  没有「手动指定用哪个播放器」的开关。
- SMTC 的所有调用都在独立的 MTA 线程上（原因见 `style-spec.md` §10.12 —— 在 UI 线程上等
  WinRT 会把整个岛卡死）。UI 侧只读快照，所以界面永远不等人。
- **歌词是第三方库查的，不是播放器自带的**：靠「曲名 + 艺人 + 时长」匹配 lrclib
  （精确 `/api/get` → 模糊 `/api/search` → 狠清洗 → 网易云兜底，共 8 级），
  失败 10 分钟后会重试一次。同名不同曲会串味；只有整行 LRC，没有 QQ 音乐那种逐字效果；
  播放器不报时间轴时
  （B 站 `pos=0/0`）只显示第一行，不滚动。
